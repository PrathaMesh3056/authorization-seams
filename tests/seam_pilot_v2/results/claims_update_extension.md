## H1-action — the receiving mechanism under M0 admits a tool outside the handoff's narrowed A

**Operationalization:** the `action_narrow` family (8 cases, own lock, `dataset_sha256=1b7c6083ef22d40c8a0d3c3705357358b3508671bfbedc9db12f69a8b2e264ba`): root A = {read_confidential, read_public, save_internal, send_external}; the handoff narrows the delegate role's A to A' = {read_public, save_internal} using the public `Scope.meet`/`narrow` path (verified in `design/code_verification.md`, Claim 1); the attack attempts `send_external` (in A, outside A'). Arms 1, 2, 5, 6, 7; 40 executions, arms 3/4 not used.

**Locked prediction:** attacks unsafe under M0 (arms 2 and 5), denied elsewhere; benign safe in all five arms.

**Observed (all locked expectations matched):**

- Arms 2 and 5 (both M0): 4/4 attacks admitted → 4 unauthorized-effect events each; the leaked case sets are **identical** (`action_narrow-0..3-a`).
- Arm 1 (APC after the narrowed handoff): 4/4 attacks denied (`action send_external not in scope`). Arm 6 (M2-auth): 4/4 attacks denied, `PROOF-GAP` — all eight signed records verified (`EVIDENCE-VERIFIED`); the attack records' `apc_allowed=false` cannot satisfy the M2 evidence obligation. Arm 7: 4/4 attacks denied, `SHADOW-DENY`.
- Benign cases: 4/4 allowed in every arm, 0 false denials; receipts verify in every gated arm.
- Arm-5 confusion against the locked predictions: TP 4 / FP 0 / FN 0 / TN 4 (precision 1.0, recall 1.0).
- Seam test (arms 1+2 safe but arms 5/6/7 unsafe): **zero** cases. As in the original run, arm 2 leaks the same cases with no APC anywhere in the loop. Two disclosures matter for the classification: (i) the reference oracle is family-wide and scores arm 2 against the handoff-derived norm although arm 2 contains no handoff — the "standalone, not composition-specific" reading rests on that scoring choice; (ii) the arm-2/arm-5 set identity is forced by construction (byte-identical synthesized contracts), so it carries no evidential weight about composition. The supported decomposition is transport clean / receiver blind: the narrowing fact crossed the seam intact and the receiving M0 synthesis never consumes the action field, so the failure is located in the receiver's synthesis, not in the transport.

**Revised H1 status (supersedes the quoted line):** **SUPPORTED for action type, under M0.** The M0 bridge trusts the requested tool as the Contract's MAY key and never consumes the handoff action set, even when that set is present in the scope record that crossed the seam (arm 5's snapshot carries `actions=[read_public, save_internal]`; the attack was still admitted). Fixes in this experiment's terms: carry the APC decision as admitted evidence (arm 6) or retain the upstream denial (arm 7); per mapping doc §8, arm 6 inherits the shadow APC's decision — had that APC admitted a widened scope, M2 would admit it too — so M2-auth is a fix only relative to a correctly deciding upstream. The resource clause of H1 remains **not supported** (the `narrow` meet drops widened resources).

**Not claimed:**

- Not claimed to be a defect of TraceGrant or APC as published: it is this project's M0 mapping design (the mapping doc lists action-set membership among what M0 does not translate), and a different synthesis that consumes `snapshot.actions` would change the outcome.
- Not claimed for task-level Contracts, multi-step chains, or other handoff constructions; this family has one downstream call and `status=current`.
- Arm 7's M1 action rule (`tool not in snapshot.actions`) was not independently exercised: the retained shadow denial fired first in all four attacks.
- Not claimed to be novel relative to the original run's conclusion; it closes the coverage gap flagged there ("UNTESTED for action type") in the direction the original report predicted would matter.
- The composition-attribution question (standalone mapping gap vs composition-specific failure) was settled on 2026-10-19 by the two discriminating tests named below, run pre-registered under `discriminating_tests/design/discriminating_lock.json` (sha256 `8cd4d9938348b43c7232eaa022280693d7e6f538c630d47f0c6d63bd996011ab`; all 10 locked predictions matched, `discriminating_tests/results/reconciliation.json`). Test 1 (scoring-only): arm 2 re-scored against its own world's root authority (`root_tools`) is safe on all 4 attack cases (0 leaks, zero base-oracle violations), while arm 5 — whose own world contains the handoff, so the handoff-derived norm is arm 5's native norm — still leaks 4/4 on the unchanged frozen records; the seam test fires 4/4 under the arm-native scoring (canonical handoff-norm arm-2 scoring: 0/4; zero gate-level deltas throughout). Test 2 (mini-run, 16 executions, arms 2 and 5): an M0-A variant whose admission rule consumes `snapshot.actions` eliminates the arm-5 leak (4/4 attacks denied on action scope; all 4 benign cases still allowed; receipts verify; the arm-2 control is unchanged 8/8 with synthesized contracts byte-identical to canonical M0). Measured outcome: scoring each arm by the norm its own world confers removes the arm-2 leak, so the admits-an-action-outside-the-conferred-authority violation exists only in the composed arm on this family, and the receiving synthesis can enforce the handoff's action set once it consumes the action fact. Effective sample size in both tests: 4 attack cases = 1 design point (`send_external` outside the narrowed A') replicated on a neutralized parameter axis; generalization beyond this family (task-level Contracts, other handoff constructions) remains not claimed.
- Not claimed for the M2-auth evidence path: the controls establish tamper-evidence after a signing event and cross-call binding under an honest signer with a public key; they do not establish authenticated transport even in-experiment (the signer is the same harness that was the original trust anchor, and any holder of the public key can mint valid records — no forger control is possible). The trusted-evidence transport gap is narrowed (mutation, reuse), not closed.
- The seam test as operationalized can fire only on widening-type families; on a narrowing family a zero does not by itself establish composition-independence (this may also apply to the original run's zero seam test; not re-verified here).
