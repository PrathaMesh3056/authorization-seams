# Choices needed to make the paper executable

Primary source: the saved `sources/tracegrant-2608.21126v1.pdf`, especially pp. 5-8, 14-15 and 17. The supplied guide is secondary. This file records implementation choices, including choices that narrow the supported language; it does not assert that these are the authors' code or exact operational semantics.

| ID | Unspecified detail or boundary | Choice and consequence |
| --- | --- | --- |
| A01 | No concrete POEC serialization or complete grammar is given. | Pydantic v2 models in `implementation/models.py` define this artifact's IR. Unknown model fields are rejected. Tool names represent operations; target scope is expressed by permitted arguments, exact values, enumerations and numerical bounds. |
| A02 | Exact frozen schemas, capability profiles, role and observability catalogs are not released in the paper. | Use the explicitly synthetic `examples/frozen_registry.json`. Its tool kind, argument roles/types and result fields stand in for these catalogs. These are hand-authored fixtures, not AgentDojo native schemas. No real account, file deletion, payment or email is invoked. |
| A03 | Normalize is named but rewrite rules are absent. | Sort obligation IDs, deduplicate and sort dependency/allowed-argument lists, sort JSON object keys, preserve all other values. Do not insert defaults into tool arguments, normalize Unicode, coerce tool values or reorder evidence arrays. Canonical JSON distinguishes `1`, `1.0`, `true`, and `"1"`; NaN/Infinity are refused. Model parsing may insert IR defaults, separately from tool-value canonicalization. |
| A04 | G_h, reachability, edge classes and conditional paths are not fully defined. | Dependencies are conjunctions. Check cycles across the entire dependency graph, a conservative interpretation. Root nodes are enabled obligations with no dependencies; compute enabled reachability to a fixed point. Reject any unreachable hard node. An explicit `enabled` fixture flag represents an unreachable node. Conditional/alternative dependency languages are NOT DONE. |
| A05 | FlowSafe wording requires every authority argument, but the reported implementation missed an optional one. | Default `complete` checks every authority argument allowed by MAY, including optional schema arguments, and requires a proof for every authority argument actually supplied. An optional argument explicitly excluded by MAY needs no BIND and cannot execute. Static binding sources must be evidence prerequisites of the effect. |
| A06 | Exact mechanism causing the optional-recipient failure is unavailable. | `diagnostic_coverage_gap` deliberately validates required bindings statically and ignores optional runtime arguments absent from BIND. It is an explicit protected-state configuration and is authenticated in certificates. This is a minimal mechanistic illustration of the reported failure, not recovered author code. The default rejects fixture 03. |
| A07 | Derivation language and numerical precision are unspecified. | Allow constant/copy, canonical decimal-string-to-integer conversion, or a single-source affine derivation `x * multiplier + offset`. Use Decimal for the calculation, reject fractional integer results, and check derived-value constraints. Multi-source calculations, general expressions, arbitrary functions and the paper's bill/balance computation are NOT DONE. No eval or executable expression input. |
| A08 | Precise set selector language is unspecified. | Equality conjunction over BIND-approved structured fields. Exactly one matching record is required. A proof binds the entire candidate set, selector, selected record, binding and evidence record through SHA-256. Duplicate equal records still count as multiple matches. Structured field types are checked at admission. |
| A09 | Placement of field/integrity constraints in the IR is unspecified. | Evidence obligations contain source/query, field type/value constraints and structured integrity equality constraints; these are the source-admission part of BIND semantics. Binding rules separately constrain derived argument values at use. Integrity checks operate on provided structured fields, such as the synthetic `object_kind`; they do not authenticate who wrote them. |
| A10 | Query-result authenticity and transport interface are abstracted. | `EvidenceRecord` is supplied by a protected query adapter. It must bind the actual query tool/arguments/result. This artifact simulates that adapter; caller-created records are not cryptographically authenticated. Evidence admission, provenance and typed derivation do not establish semantic truth. Poisoned designated objects remain admissible when their structured checks pass. |
| A11 | Repeated evidence acquisition and conflicting admitted records are unspecified. | A fulfilled evidence obligation closes after one admitted record; record IDs cannot be reused. Proof construction requires exactly one admitted record for its evidence obligation. No evidence refresh/revocation protocol is implemented. At certificate use and receipt time, qualifications and record digests are rechecked. |
| A12 | Matching multiple active obligations for the same tool is unspecified. | A supplied obligation ID must match an active effect; otherwise automatic matching requires a unique active effect for the tool. Ambiguity denies the call. The harness can disambiguate by supplying an ID. |
| A13 | Budget decrement timing and fault/retry accounting are unspecified. | Effect budget decrements atomically at dispatch, never at ALLOW/issuance, and is not restored after failure or crash. Query budget decrements when a matching native-query result is submitted for admission, even if its type/integrity/state fails; a wrong tool/query is not treated as execution of the specified query. This is a simulation convention, not a full query gateway. Static budgets must cover at least one call for each enabled hard tool obligation. Optional effects may have no budget; retries require spare budget. |
| A14 | ScopeSafe's full consistency solver is unspecified. | Validate nonempty enumerations, typed exact values, valid bounds, constant consistency, intersection of dynamic BIND/MAY ranges, permitted arguments and minimum hard-obligation budgets. This is a restricted language, not a general constraint/SAT solver. |
| A15 | H's exact risk patterns and provenance tracker are not supplied. | Use the documented regex in `engine.py` for active-script markers, a few command-execution markers, instruction-hijacking text and explicit credential markers. `tainted_payloads` is trusted adapter metadata. Only an exact payload value registered in the Contract as explicitly user-authorized bypasses screening. The regex is illustrative, not a benchmark detector. H takes Eq. 5 precedence and is checked again when a certificate is used. |
| A16 | Step-up authentication channel and grant encoding are not specified. | Return STEP_UP_AUTH and keep the candidate unexecuted. Authentication UI, human approval and step-up grant issuance are NOT DONE. A planner cannot clear H by claiming approval. Certificate issuance re-evaluates Eq. 5 and refuses all non-ALLOW outcomes. |
| A17 | Cryptographic construction is intentionally open. | HMAC-SHA256 with a caller-supplied key of at least 32 bytes, constant-time MAC comparison, random 128-bit nonce, contract/registry hashes, session, binding mode, Eq. 6 fields, issue time and expiry. Use integer seconds and a default TTL of 60 seconds. The key in tests/traces is an explicitly public synthetic test key, not a credential. No key is read from the user's environment. |
| A18 | Certificate reservation, stale budgets and expiry behavior are unspecified. | Permit one unexpired outstanding certificate per obligation. Bind its tool's remaining-budget value and recheck active obligation, MAY and proofs at dispatch. Valid time interval is `[issued_at, expires_at)`. A stale certificate is not reused; the harness returns to issuance. Expired entries remain in the registry for audit. |
| A19 | Atomicity and persistence implementation is unspecified. | Pure functions copy state; a harness must retain the returned authoritative state and must not fork/replay old snapshots. `Gateway` keeps authoritative state and serializes issue/dispatch/native result/receipt with an in-process RLock. Two competing executions of the same ticket invoke the synthetic runner only once. Cross-process durability, distributed coordination, restart recovery and transactional storage are NOT DONE. |
| A20 | Native result and receipt transport formats are unspecified. | A trusted runner supplies tool, exact actual arguments, certificate nonce, boolean execution success and structured result. Match the cert, require success, check typed observable postcondition equality and reproduce the original proofs. One result is processed per dispatch, including a failed result. Receipt records link nonce, obligation and a native-result hash. Receipt signing/transport is NOT DONE; receipts live inside protected state. |
| A21 | Late result handling is unspecified. | A receipt can arrive after certificate expiry if dispatch already consumed the certificate while it was valid. Require a registered consumed certificate; expiry governs permission to dispatch, not the timing of a native return. A pre-dispatch receipt and repeated result processing are refused. |
| A22 | Retry, crashed runner and receipt fault semantics are underspecified. | A failed receipt leaves the effect ACTIVE. A fresh ticket may authorize a retry within remaining budget. A runner exception consumes the ticket and budget, marks the outcome processed, propagates the error and leaves completion closed. The crash control is reported separately with zero successful defenses. Idempotency and compensation for real services are NOT DONE. |
| A23 | Output requirements and legitimate exemption predicates are not operationally specified. | Output fixtures use exact expected JSON values. Waivers require an ACTIVE obligation with a Contract-declared exemption code; only a protected caller may apply it after checking its real-world condition. No semantic output judge or real exemption-condition verifier is implemented. The final gate checks all hard states, plus the presence of evidence/receipt/output/waiver support. Soft obligations do not gate completion. |
| A24 | Eq. 10 depends on trusted-request semantics and all reachable states. | It is an assumption, not a runtime algorithm. The Eq. 10 unit test only enumerates four candidates in a stated toy domain for a fixed deletion Contract. General semantic soundness, formal proof and complete reachability verification are NOT DONE. Static acceptance does not prove the Contract correctly represents user intent. |
| A25 | Native Contracts for the two white-box successes are unavailable. | Bill fixture uses a synthetic parsed bill object and identity affine amount derivation; it omits the reported balance obligation. Rent fixture combines notice and transaction-ID observations into one synthetic query and omits the separate scheduled-transaction query. Values 250, 7 and 1200 illustrate paper-reported paths; account identifiers and all native outcomes are synthetic. These probes demonstrate mechanisms, not native replay or ASR. |
| A26 | Requested fresh directory and dependency availability. | Created a previously absent artifact directory. Read discovery metadata and source inputs outside it, then wrote only inside it. No upstream repository was cloned or executed. Local Python 3.12.7 and pinned installed packages were used in a venv inheriting system packages because network setup was unnecessary. Automatic pytest plugin loading is disabled. The environment is documented but not hermetic. Wheel hashes and an offline dependency bundle are NOT DONE. |
| A27 | Random ticket IDs, wall-clock timings and console addresses affect exact reruns. | Preserve exact raw outputs from this run. Semantic case results are reproducible; nonces, timings, XML timestamps, paths and console memory addresses need not be byte-identical. All calculations of denominators, fractions and pytest pass counts run in Python. |

The scope covers this declared IR and trusted single-process harness boundary. It does not include the LLM compiler, real integrations, semantic authenticity validation, or the authors' experimental artifact.
